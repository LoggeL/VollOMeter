## medium: Custom drink names are rendered as HTML

id: fnd_sig-feat-ui-flow-9d0a820e08-b451_a2ab0452af
category: security
confidence: high
triage: confirmed-bug
status: open
feature: Static Web App Shell (feat_ui-flow_9d0a820e08)

evidence:
- main.js:505-513 (addCustomDrink)
- main.js:993-1013
- main.js:843-858
- main.js:459

The custom drink name is accepted from an input field and stored without escaping. When that custom drink is selected, and again when saved drink history is reloaded, the name is interpolated into a string assigned with innerHTML. A name such as `<img src=x onerror=alert(1)>` is short enough for the form's maxlength and will execute when rendered. This can read or modify the app's localStorage state and any same-origin data available to the static app.

recommendation:
Render the drink name and details with text nodes or `textContent` instead of `innerHTML`. Keep the status badge as a separately created element, as the code already does, and validate custom drink names for display length/allowed characters separately from escaping.

test analysis:
No tests were provided for custom drink creation or DOM rendering of user-provided drink names.

suggested regression test:
Add a browser or DOM test that creates a custom drink whose name contains HTML markup, selects it, and asserts the table cell displays the literal text without creating an `img` element or firing inline handlers.

minimum fix scope:
Replace the `tdName.innerHTML = nameText` custom-drink rendering paths with text-node based rendering; audit the other `innerHTML` assignments that include persisted or user-entered values.

repro:
Create a custom drink named `<img src=x onerror=alert(1)>`, then select it from Sonstiges. The table row insertion assigns the generated string to `tdName.innerHTML`, causing the handler to run.

## low: Malformed persisted state can stop the app during bootstrap

id: fnd_sig-feat-ui-flow-9d0a820e08-4ca2_ebb76bcf98
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Static Web App Shell (feat_ui-flow_9d0a820e08)

evidence:
- main.js:62-64
- main.js:415-416
- main.js:493-497 (getCustomDrinks)

The app parses localStorage values without any error handling. If `drinkHistory` is malformed, the exception occurs during script initialization before event handlers and UI state are fully set up, leaving the app unusable until storage is manually cleared. `customDrinks` has the same issue when opening the Sonstiges flow.

recommendation:
Wrap persisted-state reads in a small safe JSON helper that validates the expected shape and falls back to an empty array/object when parsing fails. Optionally remove or quarantine the bad key after detecting corruption.

test analysis:
No tests were provided for bootstrap behavior with missing, old, or corrupted localStorage data.

suggested regression test:
Add a startup test with malformed `drinkHistory` and `customDrinks` values that verifies the page still initializes and resets to empty state.

minimum fix scope:
Centralize safe parsing for `drinkHistory` and `customDrinks`, then use it at bootstrap and in `getCustomDrinks`.

repro:
Run `localStorage.setItem('drinkHistory', 'not json')` in the browser console and reload the page. `JSON.parse` throws before the rest of the app initializes.
